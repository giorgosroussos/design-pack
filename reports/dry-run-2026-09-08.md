## Friction

F1. **`stage-detect.sh` misreports the stage during Stage A.** `scripts/stage-detect.sh` lines 30–31: `if [[ ! -f QUESTIONS.md && ! -d docs/inputs ]]; then echo "A-intake"`, then A-cards only when a Blocking card lacks an Answer, else `B-fileset`. After Round A0 (QUESTIONS.md exists, empty) it prints `B-fileset`; after the last Blocking batch is answered but while Open-card batches (external, ux) are still unpresented it prints `B-fileset`; the same during the A Exit stop. A session re-entering per SKILL.md step 2 ("`B-fileset`, `B-write` → `stages/B-specify.md`") would skip extraction entirely after A0, and skip two batches later. `A-elicit.md` line 3 says Stage A ends "when no card whose `Blocks:` is `specification` lacks an `Answer:`" — consistent with the detector but inconsistent with Rounds A2… ("When every surface group is done, go to Exit"), which present non-Blocking cards too. Conversely, a Blocking card opened in Stage B (Q-015, Q-017) makes the detector print `A-cards`, pointing a re-entering session at `A-elicit.md` while the work is in B.

F2. **A wrongly worded decision record cannot be corrected, and supersession does not remove its failure.** No stage names a correction path for a `decision-added` payload that fails `check-docs` (the log is append-only, the projection is byte-compared). I followed the only mechanism the pack offers (`decision-superseded` + a new record): the superseded entry is still rendered in full by `eventlog.render_decisions` (it appends `Status: superseded by …` and then every field), and `check_citations` scans the whole of DECISIONS.md, so the failure `FAIL citations DECISIONS.md:80: `specs/README.md` §Technology baseline leaves the engine to this record does not resolve` persisted after supersession. `check_decisions` (check-docs.py ~line 330, comment "collapsed entry: heading plus status line only") assumes superseded entries are collapsed; the renderer does not collapse them. With the log append-only, the pack would fail `check-docs` forever. **I deviated**: truncated the log to seq 36 and re-appended D-007..D-010 (logged as `#DEVIATION` in commands.log). Nothing in any stage sanctions this.

F3. **The `specs/README.md` §Name citation parser is greedy.** `FILE_TOKEN_RE` + `re.match(r"\s*§\s*([A-Z][A-Za-z -]*?)(?=\s+rule\b|\s+and\b|[,;:.)`]|$)")` in check-docs.py: a named-section citation followed by ordinary prose (`§Technology baseline leaves the engine to this record`) is read as the section name up to the next punctuation. Nothing in `reference/provenance.md` or `B-specify.md` says a named citation must be immediately followed by punctuation or `and`/`rule`. This is what produced F2.

F4. **`A-elicit.md` A2.3 understates what `card-answered` needs.** Text: `"Accept recommendations" is --set recommendation_accepted=true on each card of the batch`. The tool refuses that: `log-append: card-answered needs 'answer' in its payload` (exit 2), and also needs `date` (`eventlog._validate_card`). `reference/decision-card.md` §Recording answers says "with the answer and the date"; the stage text does not. The letter of the recommended option must be extracted by the agent from the recommendation string.

F5. **Stack card contradicts the surface filter.** `templates/specs/README.md` notes: "if the stack is open, one bullet: 'Not fixed by the requirements; see Q-NNN'" and `B-specify.md` B2.2: "a stack element nobody fixed is a card, not a guess." `reference/surfaces.md` lists no surface for language/framework and says library choice within a fixed stack is never a card. To satisfy the template I wrote Q-015 as `external` (hosting provider/cost), `Blocks: specification`, which forced a mid-B2 stop the stage does not describe (B2 has no stop; only B3+ has "if a new card has Blocks: specification: stop the round").

F6. **Open cards created in Stage B are never presented to the owner.** `B-specify.md` mechanical pass step 3: "Cards with a later `Blocks:` go to `## Open` and the round continues." No later step presents them; B5.1 then instructs the agent to append `card-deferred` for every Open card whose `Blocks:` names a Phase — so the skill defers Q-016 without any owner word, while `A-elicit.md` A2.3 defines `card-deferred` as "A card the owner explicitly defers". Q-016 left Stage B unanswered and the register cannot hold its statement.

F7. **Round numbering in `B-specify.md` is ambiguous.** "## Rounds B3… — Domain files, at most four per round" is followed by "## Round B4 — Register" and "## Round B5". With two domain rounds (8 files) the second domain round has no name and "B4" is either the second domain round or the register round. The Exit report asks for "statements by provenance per file" but `extract-normative.py` prints totals only (the `--format md` table is per statement, not per file).

F8. **Template file names and section numbers are hard-coded and disagree with the stage's freedom to name/number files.** (a) `templates/TRACEABILITY.md` line 12: `specs/{{NN_TESTING}}-testing-acceptance.md` while B1.1 names the role "testing and acceptance" and the map row I was told to write is `NN-kebab-name.md`; rendered literally it fails `citations` (`is not a file`). I rendered the real name. (b) `templates/PLAN.md`: `` `{{NN_ARCH}}` §1 (layout) `` and `templates/AGENTS.md`: `` Target repository layout (`{{NN_ARCH}}` §1) `` assume the architecture file's §1 is the layout; B3's writing rules never say so. My 02 §1 was "Shape"; I appended §7 Repository layout and cited §7. (c) `templates/specs/implementation-plan.md` FND-04 cites `{{NN_L10N}}`, a localization spec no small product has; B1's role list has no localization file. I folded language into 05 §6. (d) FND-04 must be renumbered FND-03 when there is no API (template notes), so `FND-03` means different things across packs.

F9. **Stage C step C1.6 read-only pass is a no-op before the first commit.** `git ls-files -z docs/inputs | xargs -0 -r chmod 0444` lists tracked files only; the stages never say to `git add` or commit, so 0 files were made read-only and the Exit report's "how many files were set read-only" is zero. Likewise the "hard-locked from the first commit" guarantee (SKILL.md, `.doc-locks` header) is untestable in Stage C because no commit exists; `make check-locks` with no HEAD printed `clean`, which may be a fail-open rather than a check.

F10. **Rendering placeholders has no named tool.** B2.1 says "render its placeholders … and append it … with the rendered payload object on stdin"; A0.3/C1 say "Render X from the template"; `allowed-tools` lists Read/Write/Edit and specific Bash patterns but neither `sed` nor `python3 -`. Every render was an improvised heredoc/sed/python (logged as `#write`), including the JSON substitution for the seed (`python3 - … | log-append.py`), which no `Bash(...)` pattern in SKILL.md permits.

F11. **`extract-normative.py` and `normative-tagged` skip `specs/README.md`.** Both glob `[0-9][0-9]-*.md`; the product statement's `[input]` tag and any untagged `MUST` in the spec map are invisible to both. `reference/provenance.md` §Where each tag may appear lists "Spec map" as a tagged location.

F12. **A-elicit A1.5 vs eventlog ordering.** The stage says assign IDs "in the order data, security, scope, external, ux" and the projection orders by opening; a card raised later (Q-015 external, Q-017 security) necessarily breaks that reading order. Cosmetic, but the promise "IDs read in dependency order" does not survive Stage B.

F13. **Stage A Exit check-docs guidance.** "ignore failures about files that do not exist yet" — with nothing but QUESTIONS.md the run is 7 FAIL lines and exit 1; there is no flag to scope the run, so the agent has to eyeball which failures matter. Same at every B3 pass (17–31 failures of which one was real).

F14. **`docs/inputs/README.md` template's `{{ROWS}}` "Kind" enumerates `requirements, constraints, mockup…`** while A0.1 puts files under `docs/inputs/<kind>/` with plural folder names; harmless but two vocabularies.

## Defects

D1. `templates/scripts/eventlog.py` `render_decisions` renders a superseded record with its full body; `templates/scripts/check-docs.py` `check_decisions` assumes ("collapsed entry: heading plus status line only") that it is collapsed, and `check_citations` still parses the body. Consequence: a citation error inside any decision text is permanent. Error text: `FAIL citations    DECISIONS.md:80: `specs/README.md` §Technology baseline leaves the engine to this record does not resolve` (line numbers 78 before, 80 after the supersession). Reproduced with the same failing text present after `decision-superseded`.

D2. `templates/scripts/check-docs.py` named-section citation regex (`\s*§\s*([A-Z][A-Za-z -]*?)(?=\s+rule\b|\s+and\b|[,;:.)`]|$)`) treats free prose after `§Name` as part of the name. Any sentence of the form "`specs/README.md` §Provenance says that …" fails the gate.

D3. `scripts/stage-detect.sh` has no `A-cards` state for "QUESTIONS.md exists but no card was opened yet" nor for "Blocking answered, Open batches not yet presented"; it returns `B-fileset` in both (see F1). It also returns `A-cards` for a Blocking card opened during Stage B.

D4. `templates/TRACEABILITY.md` hard-codes `-testing-acceptance.md`; rendered literally against a file named per B1 (`08-testing-and-acceptance.md`) it fails `citations`. (Not executed; read from `check_citations`: `` `specs/(\d{2}-[a-z0-9-]+\.md)` `` existence check.)

D5. `A-elicit.md` A2.3's `--set recommendation_accepted=true` alone is rejected by `log-append.py`: `log-append: card-answered needs 'answer' in its payload` (exit 2).

No script crashed; every named tool ran as documented apart from the above.
